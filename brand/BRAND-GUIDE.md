# NEXUS 2.0 · Brand system
Version 0.1.0 · Approval candidate · October 19, 2026

Read DECISIONS.md for A (approved), P (proposed), and B (blocked) authority. All exact measurements, copy examples and asset constructions below are P unless explicitly marked A.

## 1. Identity and positioning
A: NEXUS by Science By Hugs. Premium, flat, minimal; cinematic at entry, calm in use. The product remains the visual focal point. Apple-inspired simplicity describes restraint and clarity, not permission to copy Apple's marks, screens or trade dress.
P: Positioning statement: “A considered storefront from Science By Hugs, built around clear information and authentic product presentation.” This is internal positioning, not a verified product benefit claim. Personality: composed, precise, warm, quietly confident. Avoid clinical authority cues, luxury clichés, visual noise and unsupported scientific promises. Science By Hugs is the endorsement; do not infer a legal corporate relationship or modify its existing identity without parent-brand review.

## 2. Logo system
A: Brand spelling NEXUS and Science By Hugs. P: Primary lockup NEXUS. above “by Science By Hugs”; secondary horizontal lockup for narrow headers; approved lowercase n. app symbol on Muted with dark Slate lettering; earlier uppercase N and embracing studies are superseded/rejected. Dot choice is pending. Never replace existing approved masters with these studies by default.
P: Clear space at least half the cap-height of N on every side; nothing including container edges may enter it. Minimum wordmark width 120 CSS px; endorsed lockup 180 CSS px; icon artwork 24 px, with interactive container at least 48. At smaller sizes omit the endorsement and put the full brand in accessible adjacent text. Print minimum lockup width 35 mm, subject to proof legibility.
Use porcelain on Slate, Slate/navigation on porcelain, pure monochrome only for constrained reproduction. No gradient, bevel, glow, tilt, stretching, busy photo backing, alternate endorsement or arbitrary letter spacing. Keep safe margins separate from clear space. Live-text SVG studies are editable references; approved masters require intentional kerning, outlined paths, optical review at minimum sizes, font-rights evidence, and export QA.
P: Export outlined SVG master, transparent PNG at 1x/2x/3x and print PDF with proofed color conversion. Do not treat hexadecimal values as CMYK recipes. Supply an accessible name “NEXUS by Science By Hugs” once; decorative repeats are hidden from assistive technology. Logo is never the only home-navigation label.

## 3. Slate color system
A: Background #222629; surface #303639; primary text/porcelain #F0F1EF; secondary text #A8B0B2; navigation #171A1C. Primary buttons porcelain with dark text.
P: Primary action foreground #171A1C. Secondary actions use transparent fill, porcelain label and secondary-text border. Use secondary text as the control boundary where required; the card surface alone does not distinguish an interactive field from its background. Reserve porcelain for information hierarchy and action, not large decorative slabs.
P: Keep feedback monochrome for this release: success/check + explicit text; warning/triangle + text; error/exclamation + message; information/info icon + text. No new status hues are proposed. Never depend on color or icon alone. Error border uses porcelain with error label. Disabled controls retain readable text and an explicit disabled state; no global opacity token. Pending or unavailable products must say why. See CONTRAST.md for numeric checks. Photographic backgrounds require an opaque text panel unless their full crop is verified.

## 4. Typography
A: Clean, modern, slightly editorial. P: Native system sans across platforms: iOS system font; Android default system sans; web `system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`. Exact glyph shapes differ; preserve hierarchy instead of assuming pixel-identical typography. Do not distribute SF font files as web assets. No paid font dependency proposed. Any later bundled font needs a license record and subset/language review.
P type scale (size/line height, weight): display 56/60 500 desktop, 40/44 500 phone; h1 40/48 500 desktop, 32/40 500 phone; h2 28/36 500; h3 22/28 600; body 16/24 400; supporting 14/20 400; label 14/20 600; caption 12/16 400. Letter spacing 0 body, -0.02em display, +0.08em short uppercase eyebrow. Never uppercase paragraphs. Caption is metadata only, never essential price, warnings or instructions. Product names wrap; no ellipsis hiding variants. Use tabular numerals for price/quantity if available. Headings sentence case; NEXUS stays uppercase. Body measure 45–75 characters. Follow user font scaling; layout grows rather than clips.

## 5. Spacing, layout and shape
P: Base 4; spacing 4,8,12,16,24,32,48,64,96. Component padding 16–24; page gutters 20 phone/32 tablet/48 desktop. Maximum content width 1280; reading width 680. Radius 8 controls, 12 cards, 16 dialogs; circular utility icons only where useful. Flat 1-unit borders, no decorative elevation; modal scrim may use 64% navigation color. Focus rings are not decorative shadows.
P: Web ranges compact <600, medium 600–1023, wide ≥1024 CSS px; 4/8/12 layout columns with gaps 16/24/32. Product grid: one column at very narrow widths or large text; two on typical phones when each card remains ≥152; three on medium; four on wide if each card ≥220. Collapse columns as content requires. Avoid hard device detection. Native layouts use available logical width; px tokens map to CSS px on web, pt on iOS and dp on Android; type maps to scalable native units. Physical pixels are export details only.

All P. Every component needs default, interaction, keyboard-focus, disabled, loading and error/empty/success states where relevant. No hover-only information.

| Hover / pressed / focus | Primary hover fill #A8B0B2; pressed same fill plus 1-unit inset position only if motion allowed; focus 2-unit porcelain ring with 3-unit background gap; selection uses check or underline, not color alone |

## 7. Iconography
P: One coherent outline family; 24×24 viewbox, 1.75-unit stroke, rounded caps/joins, consistent optical weight. Do not mix filled and outline sets except a deliberate selected-state pair. Name icons by function (search, bag, account, favorite, close, check, warning), not visual analogy. 16-unit icons only for noninteractive metadata. RTL mirrors directional controls where meaning requires; brand marks do not mirror. Inventory licenses before adopting a library; no icon library is bundled here.

## 8. Product imagery and packaging fidelity
A: Initial product presentation uses photorealistic 3D of actual physical packaging. B: No verified packaging reference pack was supplied for this branding work; existing repository imagery has not been validated against real packaging. Accordingly this package contains no product image, invented vial, pseudo-label, model or animation claiming to represent stock.
P production gate: obtain signed reference pack per SKU: multi-angle photos, ruler measurements, label artwork/dieline, cap and seal construction, glass/material and finish specification, actual contents/fill level where visible, and SKU/version/date. Record image rights, supplier/source and reviewer. Label artwork must be applied as the actual artwork, never generated text. Match bottle profile, proportions, cap, crimp, label placement, typography and all visible wording. Do not add dosage, concentration, certification, efficacy, sterility or regulatory symbols. Do not infer internal contents or color from product names.
P image direction: neutral Slate background, large soft key at roughly 45°, gentle opposing fill, restrained grounded contact shadow, plausible glass reflections, no decorative colored liquid or invented mist. Physically plausible materials; never use lighting to hide label mismatch. Consistent camera height and perspective per series; suggested 70–100mm equivalent lens tested against reference. Front view shows full package; include separate detail and rear-label views. Crop with 10% safe margin; do not crop closures or required identity. Keep product color neutral; compare with color-managed reference.
P deliverables: editable scene with dependencies and rights manifest; lossless 2400×3000 sRGB 4:5 master, 2400×2400 square, 3200×1800 hero where needed; derived web/native sizes selected after performance audit. No upscale presented as new detail. Alpha PNG only for verified cutouts; JPEG/WebP/AVIF derivatives after visual comparison. Keep unmodified reference files and hashes. File convention `nexus_<sku>_<packrev>_<view>_<locale>_<size>_vNN.ext`. Never place preview images into approved assets. Render disclosure, if used: “3D rendering of current packaging”; exact placement proposed, subject to product review. Alt text describes verified product/view; repeat no unverified claims. Packaging changes invalidate affected renders until reapproved.

## 9. Motion and launch
A: Cinematic vial opening; calm storefront. P storyboard: 0–0.4s Slate field and soft light; 0.4–1.6s verified vial resolves with subtle camera movement; 1.6–2.4s wordmark and transition to ready storefront. Keep package intact: no opening cap, liquid movement or physical behavior unless evidenced. Do not animate an invented vial while references are missing. Review can use only a wordmark still.
P: Optional first-launch sequence; visible Skip from first frame; returning launch goes directly to storefront, with replay available only if later approved. Never delay a usable screen waiting for media; still fallback when offline or load fails. No autoplay audio, flashing, mandatory rotation or motion coupled to authentication. Reduced-motion mode immediately shows still wordmark/storefront, with no zoom/parallax or camera movement. UI durations 160ms small feedback, 240ms panel change, cubic-bezier(0.2,0,0,1). Functional state changes remain perceivable with animation disabled.

## 10. Voice and editorial templates
P: Be concise, specific and considerate. Describe what is known and what happens next. Use active verbs, sentence case and concrete labels. Avoid hype, exclamation marks, invented scarcity, medical advice, guaranteed outcomes and unsupported scientific claims. “Premium” describes execution internally; do not repeatedly call products premium. Avoid jokes around failures, orders or privacy.
Examples (templates, not live facts): empty bag “Your bag is empty.” / “Explore products”; search “No results for ‘{query}’.” / “Try another name or clear your filters.”; unavailable “Currently unavailable.” / “Notify me” only where implemented; failure “We couldn’t update your bag. Please try again.”; success “Added to bag.”; order “Order {number} confirmed.” only after confirmation; notification “Your order status has changed. Open NEXUS for details.” Avoid sensitive product details on lock screens by default.
Storefront editorial headline proposal: “Considered in every detail.” Pair with factual copy, not implied efficacy. Product copy structure: exact product name → verified variant/quantity → verified descriptive facts → current fulfillment information → approved notices. Each factual statement needs catalog provenance. Use locale-aware currency/date formats; do not invent a shipping ETA or support SLA. Translate meaning with native review; do not force English line breaks.

## 11. Responsive platform standards
P: Shared identity and content hierarchy, platform-native behavior. iOS: respect safe areas, Dynamic Type, VoiceOver, native back and sheet conventions, system authentication. Android: window insets, font scale, TalkBack, system back and predictive-back compatibility during later implementation. Web: semantic headings/landmarks, correct buttons/links, keyboard navigation, visible focus and responsive reflow. Brand typography does not override user scaling or platform accessibility settings.
P: 48×48 logical-unit minimum interaction target across all platforms; native font scaling and web zoom to 200%, reflow at 320 CSS px, no lost content at large text. Use 8-unit spacing between adjacent targets where feasible. Support portrait/landscape and split view; no fixed-height text containers. Test long names, translated strings, keyboards and safe-area intrusion. Launch art is distinct from OS launch screen, which must be a static, lightweight matching surface.
App identity: owner approved the current lowercase n. vector, Muted #A8B0B2 background and dark Slate #171A1C lettering on October 19, 2026. P: platform-specific export geometry requires device QA. Provide editable square vector, then platform exports from current tooling. Android adaptive icon has separate foreground/background plus monochrome layer, with critical content inside platform safe region; iOS artwork is supplied without pre-baked corner masking and verified in current asset tooling. Web favicon uses simplified mark at 16/32/48 and larger 192/512 installable assets where needed. Store screenshots use real reviewed UI and verified products; no concept presented as shipped. Exact store export sizes must be verified at release; none are claimed complete here.

## 12. Accessibility acceptance
P target WCAG 2.2 AA for web and equivalent native accessibility outcomes. Normal text ≥4.5:1, large text ≥3:1; meaningful control boundaries and graphical indicators ≥3:1 against adjacent color. Contrast is necessary but not sufficient. Palette pairings are calculated in CONTRAST.md. Do not use secondary text on porcelain. Surface/nav boundaries alone fail 3:1; add an outline or non-color affordance where identification depends on it.
P checks: screen-reader labels and reading order; error association and summary; announced asynchronous outcomes; keyboard focus visible and not obscured; no keyboard trap except deliberate dismissible dialog focus management; skip navigation; no drag-only task; no color-only state; password managers and paste supported; reduced motion; 200% zoom/320 reflow; meaningful image alternatives; accessible provider controls; touch targets and contrast in every state. Test VoiceOver/Safari, TalkBack/Chrome and keyboard/screen-reader web workflows after implementation. This portfolio is not a claim that the existing application conforms.
Sources checked October 19, 2026: https://www.w3.org/TR/WCAG22/ ; https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html ; https://developer.android.com/guide/topics/ui/accessibility/views/apps-views ; https://developer.apple.com/design/human-interface-guidelines/accessibility . The proposed 48-unit system target is a NEXUS choice, aligned with Android guidance; it is not a claim that WCAG requires 48 CSS px.

## 13. Governance and release
P: Brand owner approves identity/voice; packaging owner verifies each SKU; designer maintains masters; accessibility reviewer validates outcomes; release custodian signs and tags releases. Names remain B06. No contributor or AI output self-approves an asset.
Lifecycle: draft → review → approved → deprecated. Store approved and proposal assets separately. Every asset has ID, status, version, source/rights, owner, platform, usage and replacement record. Use ASSET-INVENTORY.csv; add checksum for approved binaries. Tokens carry status per leaf; approved palette values must not be confused with proposed assignments or numeric scales.
P: v0.x candidates; v1.0.0 first signed system. Major = identity/token contract breaking change; minor = additive approved component or asset; patch = correction with no intentional visual change. Record rationale, affected files/screens, tests, approver/date, migration and rollback reference in CHANGELOG. Keep immutable release tags/snapshots. Resolve authority in order: explicit later owner approval → signed current release → source decision ledger → drafts; never silently override an approved decision.
Review gates: recover missing blueprint and existing brand assets; approve P01–P08; receive packaging source pack; create and approve final masters; verify licenses and platform exports; then open a separate implementation change. Repository placement and generated platform adapters are future work. Maintain old release until replacements are approved; never use screenshots as token authority.
